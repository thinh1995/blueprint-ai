# Whole-Project Documentation Update Prompt

Use this prompt in Codex, Claude Code, or another AI agent after opening the project root. It initializes or refreshes the actual project notes in `docs/current/`; it must not rewrite reusable material in `docs/templates/`.

## First documentation pass

```text
Hãy cập nhật toàn bộ tài liệu dự án theo evidence-first workflow.

Trước khi viết, đọc AGENTS.md, docs/current/Vault Index MOC.md, docs/current/00 - Onboarding/3. AI Agent Workflow.md và source hiện hữu. Kiểm tra host có capability tạo sub-agent/delegation không. Nếu có, BẮT BUỘC tạo các sub-agent phù hợp trước khi viết: source discovery; architecture/API; product/BA; QA/traceability. Giao cho từng sub-agent một câu hỏi giới hạn và ownership rõ ràng; mặc định chúng chỉ đọc source. Mỗi agent phải trả source path/command output và Fact / Assumption / Unknown. Agent chính đối chiếu mâu thuẫn và là agent duy nhất ghi các note dùng chung. Nếu host không có delegation, ghi rõ capability thiếu và chạy các phase tương đương theo tuần tự; không nói rằng đã tạo sub-agent.

Xác minh source directories, runtime, route/API, schema, permission, queue/scheduler, integrations và test commands bằng file path hoặc command output.

Sau đó cập nhật docs/current (không sửa docs/templates hoặc docs/internal):
1. Setup Guide với project layout, commands đã xác minh và environment an toàn.
2. Overview và BA Foundation với scope, stakeholder, goals, assumptions, risks, decision log và glossary.
3. Architecture, API, backend, infrastructure, user manual khi phù hợp với source thực tế.
4. Tạo hoặc cập nhật mỗi feature thực trong docs/current/05 - Product Features/, bắt đầu từ docs/templates/feature-spec-template/ nếu cần.
5. Thêm Mermaid diagrams theo docs/current/08 - Diagram Standards/Diagram Standards.md khi luồng, state, data boundary hoặc architecture cần được làm rõ.

Phân biệt Fact / Assumption / Unknown. Không bịa requirement, command, link, API hoặc diagram. Không coi template/sample là source of truth. Nếu thiếu owner, acceptance criteria hoặc source authority, dừng và nêu câu hỏi cần quyết định.

Cuối cùng, chạy validation docs phù hợp, báo cáo files đã cập nhật, các command/result và các Unknown còn lại. Với behavior-changing task, tạo task evidence mới trong docs/current/00 - Onboarding/task-evidence/ từ docs/templates/task-evidence-template.md.
```

## Refresh after a change

```text
Hãy refresh tài liệu dự án sau thay đổi hiện tại. Đọc AGENTS.md, task evidence, Product/Tech/QA Spec liên quan và diff/source hiện hữu trước. Kiểm tra capability delegation của host. Nếu có, BẮT BUỘC tạo sub-agent phù hợp cho source discovery, architecture/API, product/BA và QA/traceability trước khi ghi; giới hạn ownership, thu evidence và tổng hợp mâu thuẫn như workflow khởi tạo. Nếu không có capability, ghi fallback tuần tự và không tuyên bố đã delegate. Chỉ cập nhật docs/current bị ảnh hưởng; không sửa docs/templates hoặc docs/internal. Đồng bộ acceptance criteria, Mermaid diagram, API/schema/permission/queue/user-flow và QA traceability khi behavior thay đổi. Nếu thiếu authority, owner hoặc acceptance criteria, dừng và nêu quyết định cần có; không tự suy diễn. Với behavior-changing task, tạo task evidence mới và map từng AC tới validation trước khi kết thúc. Chạy `python3 tools/validate-docs.py` và validator evidence phù hợp. Báo cáo Fact / Assumption / Unknown, validation đã chạy và residual risk.
```

## Expected result

- `docs/current/` phản ánh sự thật của dự án đang làm.
- `docs/templates/` chỉ là material để copy/tái sử dụng.
- `docs/internal/` không được cài vào project downstream.
