# Whole-Project Documentation Update Prompt

Use this prompt in Codex, Claude Code, or another AI agent after opening the project root. It initializes or refreshes the actual project notes in `docs/current/`; it must not rewrite reusable material in `docs/templates/`.

> **Slash-command shortcut (Claude Code, Antigravity CLI, Qwen Code):** When installed with default skills enabled, run `/sdd-docs` for the first documentation pass or `/sdd-docs refresh` after a code/behavior change. The prompt blocks below remain the canonical instructions that `/sdd-docs` delegates to—and the direct copy-paste or natural-language fallback for Codex, Gemma, or `--without-skills` setups.

## First documentation pass

```text
Hãy cập nhật toàn bộ tài liệu dự án theo evidence-first workflow.

Trước khi viết, đọc AGENTS.md, docs/current/Vault Index MOC.md, docs/current/00 - Onboarding/3. AI Agent Workflow.md và source hiện hữu. AI Agent Workflow là policy chuẩn cho evidence, authority, delegation và điều kiện dừng. Kiểm tra host có capability tạo sub-agent/delegation không. Nếu có, BẮT BUỘC tạo các sub-agent phù hợp trước khi viết: source discovery; architecture/API; product/BA; QA/traceability. Giao câu hỏi giới hạn và ownership rõ ràng; mặc định chỉ đọc source. Mỗi handoff phải có source path/command output và Fact / Assumption / Unknown; agent chính xử lý mâu thuẫn và là agent duy nhất ghi note dùng chung. Nếu host không có delegation, ghi capability thiếu, chạy phase tương đương tuần tự, và không nói rằng đã tạo sub-agent.

Xác minh source directories, runtime, route/API, schema, permission, queue/scheduler, integrations và test commands bằng file path hoặc command output.

Sau đó cập nhật docs/current (không sửa docs/templates hoặc docs/internal):
1. Setup Guide với project layout, commands đã xác minh và environment an toàn.
2. Overview và BA Foundation với scope, stakeholder, goals, assumptions, risks, decision log và glossary.
3. Architecture, API, backend, infrastructure, user manual khi phù hợp với source thực tế.
4. Tạo hoặc cập nhật mỗi feature thực trong docs/current/05 - Product Features/, bắt đầu từ docs/templates/feature-spec-template/ nếu cần.
5. Thêm Mermaid diagrams theo docs/current/08 - Diagram Standards/Diagram Standards.md khi luồng, state, data boundary hoặc architecture cần được làm rõ.

Phân biệt Fact / Assumption / Unknown. Không bịa requirement, command, link, API hoặc diagram. Không coi template/sample là source of truth. Nếu thiếu owner, acceptance criteria hoặc source authority, dừng và nêu câu hỏi cần quyết định.

Cuối cùng, chạy validation docs phù hợp, báo cáo files đã cập nhật, các command/result và các Unknown còn lại. Với behavior-changing task, tạo task evidence mới trong task-evidence/ từ docs/templates/3. Task Evidence Template.md.
```

## Refresh after a change

```text
Hãy refresh tài liệu dự án sau thay đổi hiện tại. Đọc AGENTS.md, AI Agent Workflow, task evidence, Product/Tech/QA Spec liên quan và diff/source hiện hữu trước. Áp dụng workflow delegation/evidence chuẩn: nếu host có capability, BẮT BUỘC tạo source discovery, architecture/API, product/BA và QA/traceability trước khi ghi; nếu không, ghi fallback tuần tự và không tuyên bố đã delegate. Chỉ cập nhật docs/current bị ảnh hưởng; không sửa docs/templates hoặc docs/internal. Đồng bộ acceptance criteria, Mermaid diagram, API/schema/permission/queue/user-flow và QA traceability khi behavior thay đổi. Nếu thiếu authority, owner hoặc acceptance criteria, dừng và nêu quyết định cần có. Với behavior-changing task, tạo task evidence mới, map từng AC tới validation, chạy `python3 tools/validate-docs.py` và validator evidence phù hợp, rồi báo cáo Fact / Assumption / Unknown, validation và residual risk.
```

## Expected result

- `docs/current/` phản ánh sự thật của dự án đang làm.
- `docs/templates/` chỉ là material để copy/tái sử dụng.
- `docs/internal/` không được cài vào project downstream.
