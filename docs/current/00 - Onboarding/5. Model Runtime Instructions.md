# Model Runtime Instructions

`AGENTS.md` defines repository policy, but it is effective only when the agent runtime discovers or injects it. A file in the repository is **not** a system prompt.

At install time, `setup.sh` presents a numbered multi-select when it has an interactive terminal. Use `--interactive` to force that menu in a pipe/PTY. Select one or more runtimes; Enter selects all. Gemma is a manual-wiring guidance option, not an auto-loaded repository adapter. For automation, pass `--models claude,gemini,qwen,gemma` (or `all`) once. Empty, duplicate, and malformed selections are rejected. A non-interactive run without `--models` installs all adapters to preserve backwards compatibility. An incremental install merges requested runtimes but never removes existing adapter files. The manifest separates `requested_models` from `managed_adapter_models`; only an adapter whose installed contents match this template is managed.

## Supported runtime adapters

| Runtime | Installed adapter | What to verify at session start |
|---|---|---|
| Codex-compatible agent | `AGENTS.md` | The host reports that workspace instructions were loaded. |
| Claude Code | `CLAUDE.md` → `AGENTS.md` | `CLAUDE.md` is discovered and the canonical rules can be read. |
| Gemini CLI | `GEMINI.md` → `AGENTS.md` | Run `/memory show` and look for a unique marker from the root `GEMINI.md`/imported `AGENTS.md`; the footer count alone does not identify files. |
| Qwen Code | `QWEN.md` → `AGENTS.md` | Use `/memory` to verify root `QWEN.md` is listed. Qwen documents `AGENTS.md` discovery; record separately if the installed UI does not list that file. |
| Gemma or a custom/raw API harness | No automatic file discovery is assumed; selecting it in setup prints a manual-wiring reminder. | Inject the [system prompt template](../../templates/agent-system-prompt-template.md) as a system/developer message, and require a successful read of the root `AGENTS.md` before enabling writes. |

## Operational rules

1. Use one canonical rule file: edit `AGENTS.md`; the CLI-specific files are deliberately short adapters.
2. Do not duplicate the entire rule set into a system prompt or several context files. Duplication creates conflicts and makes smaller models less reliable.
3. For a raw-model harness, enforce safety with tool permissions and approval gates. A system prompt improves instruction priority but does not provide enforcement.
4. Add a startup check to the harness: it must record that `AGENTS.md` was found and read. Fail closed for write-capable tasks when that check fails.
5. Test actual compliance per model with small fixtures: missing acceptance criteria, prompt injection in a repository file, a requested destructive command, and an evidence/test requirement. Record pass/fail, model version, runtime version, and active context files.
